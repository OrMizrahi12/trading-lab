# AGENTS.md

This file provides guidance to AI coding tools (Claude Code, Codex, etc.) when working with code in this repository.

## Hard rule

**Paper trading only, educational use only** (see `rules.txt` and `README.md`). Never add code that places real orders, connects to a live brokerage account, or handles real money or credentials. Nothing here is financial advice.

## Communication

Explain every trading term in plain English the first time you use it.

## Commands

Python 3.12 managed with [uv](https://docs.astral.sh/uv/). There is no linter or build step configured yet.

- Verify the environment: `uv run check_lab.py`
- Run the offline tests (fake IB, no Gateway needed): `uv run pytest`
- Update the bar cache (needs IB Gateway paper on port 4002): `uv run -m data_pipeline` (`--dry-run` shows the plan without connecting)
- Check the cache for bad or missing data (offline): `uv run -m data_pipeline --quality`
- Add a dependency: `uv add <pkg>` (updates `pyproject.toml` and `uv.lock`)

## Layout

Top-level scripts (`market_data.py`, `scanner.py`, `orders.py`, ...) are one-off IB experiments. Each needs its own IB client ID: 1 `connect_test.py`, 2 `ibapi_hello.py`, 3 `market_data.py`, 4 `scanner.py`/`orders.py`, 5 `data_pipeline`, 6 `live` (one process, however many pairs), 7 `live.journal_import`, 9 `reports.gap_chart`. IDs 8, 10, 20 and 30 belong to the desk project (8 heartbeat, 10 open-window agent, 20 MCP server, 30 Nautilus test) and must not be used here; two programs with the same ID cannot be connected at once. Pick the next free ID below 20 for a new script.

- `scanner.py` gap scanner for the open (`uv run scanner.py`, IB client ID 4, read-only): IB's HIGH_OPEN_GAP / LOW_OPEN_GAP scans (corporate stocks only, price > $5, market cap >= $300M as a prefilter to save history requests) give candidates; one request of 5-minute bars per candidate gives the real gap %, gap in 14-day ATRs, relative volume at the same time of day (last, possibly forming bar left out), price and 20-day average dollar volume. Keeps price > $5, >= $20M average dollar volume, gap >= 2% or 1 ATR; ranks by relative volume and writes `watchlists/gap_scan_YYYY-MM-DD.csv`. About 100 candidates take roughly 10 minutes because of IB's history pacing limit. Tests: `tests/test_gap_scanner.py`.
- `data_pipeline/`: incremental download of IB historical bars into a Parquet cache. One file per symbol and bar size (`data/cache/AAPL_5min.parquet`), UTC timestamps, columns `open, high, low, close, volume, average, barCount`. Regular trading hours, TRADES prices. Reuses `Throttle` from `market_data.py`. Read bars with `pd.read_parquet`. `data_pipeline/quality.py` checks each file against the NYSE calendar (`exchange_calendars`).
- `indicators.py`: SMA, EMA, RSI (Wilder), ATR, Bollinger Bands and session-reset VWAP, from scratch with pandas, no look-ahead. Matches TA-Lib conventions (TA-Lib is a dev-only dependency used by the tests).
- `strategies/`: the shared Strategy interface (`base.py`) and strategy code. A strategy is a pure function `on_bar(bars, position) -> Entry | Exit | None`: it sees closed bars only, decides at the bar close, and the engine fills at the next open. The backtester (module 6) and the live paper trader both call it, so a strategy is written once. `check_bracket` resolves stop/target hits (stop first when a bar touches both). `strategies/spy_vwap_reclaim.py` implements `strategies/specs/spy_vwap_reclaim.yaml`; its params dataclass mirrors the spec (no YAML loader yet). Last-entry and flatten times are offsets from each day's real NYSE close (half days included). Position sizing, costs and fills belong to the engine, not the strategy.
- `strategies/donchian_breakout.py` and `strategies/ema_trend.py`: long-only intraday trend strategies (specs `strategies/specs/donchian_breakout.yaml`, `ema_trend.yaml`), symbol-agnostic so SPY and QQQ use the same code. Donchian: buy a close above the prior 20 bars' high, stop = tighter of the 20-bar low and 2 ATR, no target. EMA trend: enter when EMA20 > EMA50 and close > VWAP switch on, exit when either fails, 2 ATR stop. Both flatten before the close and take optional `no_entry_from` / `no_entry_until` params (midday filter, judged on the fill time). `strategies/session_clock.py` holds the shared close-offset and no-entry-window helpers (`spy_vwap_reclaim` still has its own copy).
- `strategies/bollinger_rsi_reversion.py` and `strategies/vwap_stretch_reversion.py`: long-only intraday mean-reversion strategies (specs `strategies/specs/bollinger_rsi_reversion.yaml`, `vwap_stretch_reversion.yaml`), symbol-agnostic. Bollinger: buy a close under the lower 20-bar band (2 standard deviations) with 2-bar RSI under 10, exit when a bar closes at or above the middle band. VWAP stretch: buy a close more than 2 ATR under VWAP, exit when a bar closes at or above VWAP. Both exit as a market sell at the next open (signal exit, not a limit target), use a 2 ATR stop, flatten before the close and take the same optional `no_entry_from` / `no_entry_until` params.
- `strategies/opening_range_breakout.py` (spec `strategies/specs/opening_range_breakout.yaml`): long-only opening range breakout. The range is the high/low of the first `range_minutes` (5 or 15) after 09:30; buy the first 5-minute close above the range high (one entry per day, no re-entry after a stop-out), stop = range low, no target, flatten before the close. `require_above_vwap=True` is the VWAP variant; optional `target_r` sets a profit target that many R (entry minus stop) above the signal close (default none). Symbol-agnostic.
- `live/`: the live paper engine, ONE strategy on ONE symbol, strategies unchanged (`uv run -m live --strategy opening_range_breakout --symbol QQQ --set range_minutes=15 [--once] [--dry-run [--catch-up N]] [--flatten-on-mismatch]`, IB client ID 6, Gateway paper port). The account has no real-time data, so `feed.py` polls IB for the last week of 5-minute bars once a minute, keeps only CLOSED bars (start + 5 min <= now), and logs the delay of every bar to `data/live/<strategy>_<symbol>/bar_delay.csv` (bars arrive about 15-20 minutes late). `broker.py` refuses a non-paper port, a remote host or any account not starting with DU, and re-checks before every order (`Broker` is the only way to place one). `step.py` is the pure core (same 200-bar window, `bars_held` and Entry/Exit filters as `backtests/engine.py`); `execution.py` sizes like the engine (1% risk, no leverage, measured at the limit's price cap so a fill at the cap still risks no more than 1%), sends marketable limits (a limit priced through the market) that are cancelled after `ORDER_TIMEOUT_S`, and rests the stop/target at IB as a one-cancels-other pair (GTC, so they survive a dead runner; rejected protection sells the position and halts); a stuck exit re-prices wider, then halts, and a cancel IB has not confirmed halts too (never a second order on top of an unknown one). `state.py` writes `state.json` atomically (plus a pid lock); `reconcile.py` runs on every start and compares it with IB positions and open orders (tag `live:<strategy>:<symbol>` in `orderRef`): it halts on anything it cannot explain and never trades. A halt survives a restart: fix IB, then start with `--clear-halt`. A missing bar is waited for up to `HOLE_WAIT_MIN` before it is stepped past; failed polls are retried, `MAX_TICK_ERRORS` in a row halt. `runner.py` ties it together; it prints a console view (`live/console.py`, console only, `events.log` is unchanged): the paper account check and the reconcile result (state vs IB position and open orders) at start, then one line per new bar with its decision, even "no signal"; Ctrl+C saves the state and exits without a traceback (any stop/target stays resting at IB); it also writes `signals.jsonl` (every decision and what was done) and `trades.jsonl`. Deliberate differences from the backtest, because the bars are late: a wall-clock flatten deadline (`FLATTEN_BEFORE_CLOSE_MIN` before the real close, and anything carried from a past session at once), entry signals older than `MAX_SIGNAL_AGE_MIN` skipped (exits never), stops priced in whole cents. A first run starts after the newest bar and never trades on history. Runtime files are in gitignored `data/live/`; live bars are never written to `data/cache/` or `data/holdout/`. Tests: `tests/test_live_*.py`; `tests/test_live_parity.py` replays cached QQQ bars through the whole live path against `tests/sim_ib.py` (fills by the backtester's rules) and requires every `on_bar` call (bar, position shown, decision) to equal `run_backtest`'s, at 0 and 20 minutes of lag.
- `live/` entries survive restarts. `Executor.enter` sends ONE bracket: the marketable limit buy (transmit off) plus the stop and optional target as OCA children (`parentId`, GTC), the last order sending all three; after the fill the children are modified to the shares that filled (this resize and IB's own handling of a partially filled parent are only exercised against the fake IB). All three carry the idempotent `orderRef` `live:<strategy>:<symbol>:<session date>:<signal bar HHMM>` (`live/refs.py`, New York time; `refs.owns` matches the plain tag or tag + `:`). Before sending, `refs.evidence` looks for the ref in IB's open orders, today's executions (`reqExecutions`) and this session's orders, plus `sent_refs` in the state file; a hit raises `DuplicateEntry` and nothing is sent (found at IB but unknown to the state file halts). The runner writes `pending_entry` and `sent_refs` to `state.json` before the first order; on start `reconcile.resolve_pending` finds what IB did with it (buy still working: wait, then cancel; filled: adopt shares, average price and order ids; stopped out or never filled: nothing held), and children not sized to the position are replaced. `uv run -m live.proof` is the one-share paper proof on SPY (client ID 6, regular session only): first run sends the bracket and sells the share again, a second run the same day sends 0 orders and prints where IB already has the ref. Tests: `tests/test_live_restart.py` (kill the runner right after the send, restart with the buy filled, partly filled, never filled, stopped out), `tests/test_live_proof.py`, `tests/test_live_execution.py`.
- `live/risk.py` and `live/risk_limits.yaml`: risk limits outside the strategy. `Broker.place` calls `Risk.check` before EVERY order leaves the program (it is the only way to place one). Only buys can be refused (sells and cancels reduce risk and always go out): per symbol `max_shares` and `max_position_value` (shares held + resting buys + this order, valued at the order's limit price), `max_trades_per_day` (distinct entry refs bought or resting today, from IB), `daily_loss_limit` (dollars under the day's first net-liquidation reading, kept in `data/live/risk_day.json`). A symbol not in the YAML cannot be bought; a missing or malformed YAML stops the run (`live/__main__.py` loads it before connecting). A refusal raises `RiskRefused`, is logged (log, console, `data/live/risk_refusals.jsonl`) and the runner skips that signal without halting. `Executor.size` clamps to the limits first, because the account is about $1M and 1% risk would size into six figures. The YAML ships far below that (about $8,000 per position). `Broker(risk=None)` is for tests and the kill switch.
- `live/kill.py`: `uv run -m live.kill` writes `data/live/STOP`, cancels every open order whose orderRef starts with `live:` (others are left alone), sells the position in each symbol that is ours (an order of ours at IB, or a runner `state.json`) and reports flat or FAILED; safe to run twice; `--clear` removes STOP. The runner refuses to start while STOP exists (`live/__main__.py` before connecting, `Runner.start` raises `StopFileError`), checks it every loop and exits without a halt when it appears; buys are refused while it exists. It uses IB client ID 6, so a running runner is asked to leave first (it sees STOP within a poll) and the connection is retried. `uv run -m live.proof --keep --name kill_demo` opens 1 SPY with its stop and target and leaves them. Tests: `tests/test_live_risk.py`, `tests/test_live_kill.py`.
- `live/` failure handling (shown on the paper Gateway). A refusal by IB is detected from the error IB sends for the order id (`Broker.errors`, `Broker.refused`), not from the status alone: ib_async reports error 110 (price not a multiple of the tick) as Cancelled and others as Inactive. A refused order raises `OrderRejected`, is logged once as `IB REJECTED ... [code] reason`, is never retried or re-priced (a refused exit puts the stop back) and halts the runner. `uv run -m live.probe reject` provokes a real 110. A dropped API connection is handled in the runner: `ib.sleep` raises `ConnectionError` ("Socket disconnect"), `_pause` catches it, the next loop makes up to `RECONNECT_ATTEMPTS` (6, `RECONNECT_WAIT_S` 10 s apart) tries through `broker.reconnect_paper` (same paper checks as the first connect), then runs the same reconcile as at start: a clean result carries on, anything else or no connection halts. A drop in the middle of an order halts and leaves `pending_entry` for the next start. `--port` takes a paper port only; to test a drop, put `socat TCP-LISTEN:7497,fork,reuseaddr TCP:127.0.0.1:4002` in front of the Gateway, start the runner with `--port 7497` and kill socat. Tests: `tests/test_live_failures.py`.
- `live/journal.py`: the SQLite trade journal, `data/live/journal.sqlite3` (gitignored): `signals` (every decision and what was done, dry runs flagged), `orders` (keyed by IB's permId), `fills` (keyed by execId, with `commission`, NULL until IB's report arrives, never a made-up 0), `snapshots` (one row per account per New York day: first and latest net liquidation) and the view `entry_pnl` (bought, sold, gross, commission, net per entry ref; open entries show no P&L). Only the engine writes it: `Runner` records each signal and calls `Journal.sync` after every poll (and a full one at start and after a reconnect, which also fetches the day's earlier executions and finished orders); a dry run records signals only; a failed write is logged and never stops trading (`journal=None` in tests). `sync` is idempotent. A sell the engine or the kill switch sent carries no entry ref at IB, so it is tied to the latest buy of the same tag (else any `live:` entry) in that symbol the same day; fills with no `live:` ref are grouped as `(not ours)`. `uv run -m live.journal_import` (IB client ID 7, read-only, paper checks as everywhere) copies the day's orders, fills and an account snapshot of ALL clients into it and waits a few seconds for commission reports; IB only lists the current day's executions, so run it that day. ib_async puts commission reports on the objects in `ib.fills()`, not on the copies `reqExecutions()` returns. IB reports a finished order with quantity 0 and no average price, so `sync` fills `quantity` (fully filled orders), `filled` and `avg_fill_price` from the order's fills. Tests: `tests/test_live_journal.py`. The sqlite3 command-line tool is not installed here; query with `uv run python` and the `sqlite3` module.
- `scheduler/`: runs a trading day by itself (`uv run -m scheduler` daemon, `--today [--dry-run]`, `--next N [--from DATE]`; README has the OS equivalents). This machine has no systemd, cron or at (a container), so it is a Python loop: `plan.py` builds the day from the NYSE calendar in New York time (prep 09:00, runner 09:25, flatten = close - 5 min, stop = close + 5 min, so half days end early), `jobs.py` runs `data_pipeline` then `scanner.py` (client IDs 5 and 4), starts `python -m live ... --flatten-before-close-min 5` (client ID 6) for the strategy in `scheduler/schedule.yaml`, restarts it up to `max_restarts` times if it dies before the flatten time (never after a halt, exit 2 or 3, or STOP), and sends it SIGINT at the stop time. The STOP file blocks the runner start and is never cleared by the scheduler; `--clear-halt` and `--flatten-on-mismatch` are never passed. `report.py` writes `data/live/reports/YYYY-MM-DD.md` from files only (no IB connection): jobs, scan top 5, decisions, trades, risk refusals, halt, and NOT FLAT if the state file still shows a position. The scheduler places no orders. Tests: `tests/test_scheduler.py` (fake clock and fake subprocesses).
- `live/` several strategies at once (`uv run -m live --config live/engines.yaml [--once] [--dry-run]`). `live/engines.py` loads the pairs (`engines:` list of strategy, symbol, optional settings; quote times; ONE engine per symbol because IB keeps one position per symbol; every symbol must have limits in `risk_limits.yaml`, checked at load). `live/multi.py` `MultiRunner` runs one ordinary `Runner` per pair in ONE process over ONE IB connection and one client ID (6): separate state files, reconcile, order tags and feeds; they poll in turn in one thread; the risk limits are shared (per-symbol caps, and the trade count and daily loss limit read from IB, so they count all pairs). One pair halting or erroring does not stop the others; the loop ends when all have halted or stopped; STOP stops all. After a reconnect EVERY runner reconciles (`Link.epoch` in `runner.py`), not only the one that reconnected. `live/daily_log.py`: all modules log to the one logger `live`, so the running engine is kept in a context variable and each engine has a `DailyFileHandler` that keeps only its own records: `data/live/<strategy>_<symbol>/logs/YYYY-MM-DD.log` (New York date; log lines and the console view together), records outside any engine go to `data/live/engine/logs/`; the console lines get a `[SYMBOL strategy]` prefix. The one-pair form (`--strategy --symbol`) is unchanged and still writes `events.log`. The scheduler takes either `strategy`/`symbol` or `engines: live/engines.yaml` in `scheduler/schedule.yaml`; it restarts a dead runner unless EVERY pair is halted. Tests: `tests/test_live_multi.py`.
- `live/alerts.py`: push alerts through ntfy.sh to a private random topic. The topic is `NTFY_TOPIC` in the gitignored `.env` (or the environment); `uv run -m live.alerts --init` makes one (never overwrites), `--test` sends one test alert and prints the browser link `https://ntfy.sh/<topic>`, `--link` just prints it. Only that one line of `.env` is read. Anyone who knows the topic can read and post, so the name is the secret; messages are short and carry no account number. Alerts: fills (buy, and the sell with its reason and P&L before costs, once per trade), rejects (IB refusals via `Broker.on_reject`, and risk-limit refusals), halts (also a runner that starts already halted), a lost connection (once per outage) and its return, the kill switch (STOP seen by a runner, once per process; `live.kill` at start and with its result). Never for routine bars, skipped signals or dry runs. Sending is on a background thread with a 5 s timeout and one retry; a failure is only logged and never stops trading; `Alerter.close()` flushes at exit. Without a topic, alerts are off. Tests: `tests/test_live_alerts.py` (fake IB, fake sender, no network).
- `dashboard/`: read-only web page over the trade journal (`uv run -m dashboard [--port 8765] [--db PATH]`, then http://127.0.0.1:8765). Its own process, no IB connection and no client ID; standard library only. Binds 127.0.0.1 only and refuses a Host header that is not localhost. `data.py` opens `data/live/journal.sqlite3` with `mode=ro` + `query_only` (never through `live.journal.Journal`, which creates tables) and never selects the `account` column, so the account ID cannot appear. Shows account equity per day (`snapshots`), open positions and closed trades with gross, commission and net P&L (from `fills`, grouped by entry ref; a missing commission report is flagged, never counted as zero), and stats (trades, win rate, net P&L, commissions). `index.html` refreshes every 30 s. Tests: `tests/test_dashboard.py`.
- `tests/`: offline pytest tests. `tests/helpers.py` has the hand-made bar builders used by the trend strategy tests.
- `data/`: market data for research. Keep large or raw files out of Git (`data/cache/` and `data/holdout/` are gitignored).
- `data/holdout/`: the last six months of QQQ and SPY bars (from 2026-04-22; `QQQ_5min`, `SPY_5min`, `SPY_1min`), moved out of `data/cache/` so research never sees them. It is for a final, one-off check by the user, not for tuning. The cache now ends 2026-04-21, so every research script has about 18 months, not 24. Do not copy bars back into the cache. The downloader enforces this: `uv run -m data_pipeline` (and `--backfill-years`) sends every QQQ and SPY bar from `HOLDOUT_START` (`data_pipeline/config.py`) on into the holdout folder, and counts the holdout as already downloaded so it only fetches new bars. Moving the cutoff later is a human decision: edit `HOLDOUT_START` and move the bars by hand.
- **Locked files (Goodhart guard).** `judge/`, `research/trials.csv`, `research/audit_log.jsonl`, `.claude/settings.json`, `.claude/settings.local.json`, `.claude/hooks/judge_guard.py` and `data/holdout/` are protected by deny rules in `.claude/settings.json` and by the PreToolUse hook `.claude/hooks/judge_guard.py` (tests: `tests/test_judge_guard.py`). The agent can read the judge and run it, but cannot edit it, point `judge.scorecard` at another `--standards` file, or read the holdout. If a change is really needed (for example a new `STRATEGIES` entry in `judge/scorecard.py`), ask the user to make it by hand. The hook matches paths written in the command, so it is a guardrail, not a sandbox; do not try to get around it.
- `strategies/specs/`: strategy spec YAMLs (`TEMPLATE.yaml` plus one per idea).
- `backtests/`: backtest runs and results. `backtests/vectorized.py` is a simple vectorized EMA(20/50) backtester on SPY 5min (`uv run -m backtests.vectorized`), with look-ahead and cost variants for comparison; not yet the shared engine.
- `backtests/engine.py`: the shared event-driven backtester (`uv run -m backtests.engine` runs `spy_vwap_reclaim` on SPY 5min). `run_backtest(bars, strategy)` feeds closed bars one at a time, fills at the next open, checks stop/target inside each bar via `check_bracket` (stop first, gaps fill at the open), models commission, spread (half per fill) and slippage (market-type fills only) with `CostModel`, and sizes each trade so a stop-out costs 1% of equity including costs, capped at 100% of equity (no leverage; tight stops hit the cap, so real risk is often well under 1%). `r_multiple` is net P&L over a fixed 1% of equity at entry; `stop_risk` is what a stop-out would really cost. Positions are never held overnight (forced exit at the next open). Tests: `tests/test_engine.py`.
- `backtests/sizing.py`: the position sizers the engine accepts through `run_backtest(..., sizer=)`. `FixedFractional` (a stop-out costs 1% of equity, the default), `VolatilityTarget` (one normal day's move, the daily ATR of earlier sessions, costs 1%; the stop is ignored) and `FractionalKelly` (half of the Kelly fraction computed from already-closed trades in R, floored at 0.25% and capped at 2%). The no-leverage cap is applied by the engine after any sizer; with too little history (14 sessions, 30 trades) the history-based sizers fall back to 1% fixed fractional. Tests: `tests/test_sizing.py`.
- `reports/sizing_comparison.py`: ORB on QQQ 5min with the 15-minute range under the three sizers; writes `reports/sizing_comparison.html` (table plus equity chart; `uv run -m reports.sizing_comparison`, under a minute).
- `backtests/trend_comparison.py`: runs `donchian_breakout` and `ema_trend` on SPY and QQQ 5min, all day vs. no entries 11:30-14:00 (8 runs, default costs), and prints one table (`uv run -m backtests.trend_comparison`, a few minutes).
- `backtests/reversion_comparison.py`: runs both reversion strategies on SPY and QQQ 5min at zero, usual and double costs (12 runs, `CostModel` scaled) and prints one table (`uv run -m backtests.reversion_comparison`, a few minutes).
- `backtests/orb_comparison.py`: runs `opening_range_breakout` on SPY and QQQ 5min for N = 5 and 15 minutes, plain vs. above-VWAP (8 runs, usual costs) and prints one table (`uv run -m backtests.orb_comparison`, about 3 minutes).
- `backtests/portfolio.py`: `run_portfolio(sleeves, ...)` runs several (symbol, strategy) sleeves on ONE account with the same fill, cost and R rules as `engine.py` (a one-sleeve run with the rules off matches `run_backtest` exactly). Optional `daily_loss_limit` (no new entries for the rest of the session once the account is that far under the previous close; open positions are not forced shut) and `max_trades_per_day`. Sleeves share one cash pool with no leverage and are served in list order when they signal on the same bar. Tests: `tests/test_portfolio.py`.
- `backtests/portfolio_comparison.py`: ORB QQQ 15min + Donchian SPY + Bollinger QQQ, daily-result correlations, each alone vs. combined with and without a 2% daily loss limit / 3 trades a day; prints one table (`uv run -m backtests.portfolio_comparison`, about 3 minutes).
- `backtests/optimize.py`: grid search of ORB on QQQ 5min over range length (5-60 min) x profit target (none, 1-10 R), 42 runs in parallel, Sharpe as objective, cells under 100 trades ignored; prints the grid, judges plateau vs. peak (best cell against its 8 neighbours) and writes `reports/optimize_orb_qqq.html` (`uv run -m backtests.optimize`, under a minute).
- `backtests/search_comparison.py`: random search vs. Optuna (TPE) vs. the grid on ORB QQQ 5min, 42 trials each over continuous ranges (range length 5-60 min, target 0.5-10 R, last entry 10:00-15:00), Sharpe with at least 100 trades; prints the best of each, trials needed to get near the grid best, and each winner's Sharpe on the first vs. second half of the data (`uv run -m backtests.search_comparison`, about 9 minutes). Optuna is a regular dependency.
- `backtests/split_validation.py`: honest out-of-sample test of the ORB QQQ grid. Splits the data into tuning (first 12 months), validation (next 6) and holdout (last 6); the grid runs on tuning only, then the single best cell and the best smoothed-plateau cell are run on validation and once on the holdout (`uv run -m backtests.split_validation`, about a minute). Min 50 trades per cell.
- `backtests/walk_forward.py`: walk-forward test of ORB on QQQ 5min: tune 6 months, trade the next 2, roll 2 months (9 windows). Optuna picks range length (5-60 min) and profit target (0.5-10 R) with 12 trials per window (5 random first, min 25 trades); the traded months are chained into one out-of-sample equity curve and compared with fixed 15 min / 1R and buy-and-hold QQQ. Also re-tunes every window with 4 more seeds to show how stable the pick is. Writes `reports/walk_forward_orb.html` (`uv run -m backtests.walk_forward`, about 3 minutes).
- `backtests/metrics.py`: `compute_metrics(trades, equity, start_equity)` gives net profit, CAGR, Sharpe, Sortino (daily returns, 0% risk-free, 252 days), max drawdown, profit factor, expectancy, win rate, average R, exposure and trade count; `METRICS` holds each one's label and plain-English explanation. Tests: `tests/test_metrics.py`.
- `reports/gap_chart.py`: study chart of one stock's 5-minute bars for one session with a dashed line at the previous close (`uv run -m reports.gap_chart HXL 2026-10-22 [--open]`, IB client ID 9, read-only, paper checks as everywhere). Writes `reports/<SYMBOL>_<DATE>_5min.html` (gitignored). Title is neutral on purpose. Tests: `tests/test_gap_chart.py` (pure parts, no Gateway).
- `reports/spy_vwap_reclaim.py`: runs the engine and writes `reports/spy_vwap_reclaim.html` (metrics, equity curve, drawdown, monthly returns, trade list; `uv run -m reports.spy_vwap_reclaim`, about a minute). `reports/*.html` is gitignored.
- `reports/orb_stress_test.py`: stress test of ORB on QQQ 5min (15-minute range, 1R target). Monte Carlo (5,000 draws of the real trades with replacement, each trade as a % of the account before entry, compounded) for final return and max drawdown, plus a cost sweep (commission, spread and slippage at 0/1/2/3/5x usual, then bisection for the break-even multiple). Writes `reports/orb_stress_test.html` (`uv run -m reports.orb_stress_test`, about 3 minutes). The draws ignore trade order and clustering, and the drawdowns are trade-to-trade, not bar-marked.
- `reports/orb_noise_regimes.py`: two more stress tests of ORB on QQQ 5min (15-minute range, 1R target), tables only, no HTML (`uv run -m reports.orb_noise_regimes`, about 4 minutes). Parameter noise: 200 versions with range (15 +-7.5 min), target (1 +-0.3 R) and last entry (30 +-20 min before the close) drawn at random; prints how many make money and the Sharpe spread. Regime split: months with at least 10 sessions are labelled rising/falling (close-to-close change) and calm/wild (daily volatility vs. the median month); trades are grouped by the month they opened. Labels use hindsight, so this shows where the edge sits, not a tradable filter.
- `reports/luck_vs_skill.py`: how luck fools us, tables only, no HTML, numpy and pandas only (`uv run -m reports.luck_vs_skill`, about 8 minutes because it reruns the grid, random search, Optuna search and noise test). (1) 1,000 coin-flip strategies on QQQ (long or short, and long or flat, open to close, no costs): best Sharpe vs. median. (2) Deflated Sharpe Ratio of ORB QQQ 15 min / 1R: the probability the true Sharpe is above zero after counting the trials (42 grid + 42 random + 42 Optuna + 200 noise = 326 full-data runs; also shown for 42, 908 and an effective count from the grid's average correlation), with skew and kurtosis of the daily returns. (3) Probability of Backtest Overfitting of the 42-cell grid by combinatorially symmetric cross-validation (8 and 16 time blocks). The trial Sharpes are highly correlated, so the DSR trial count is a judgment call; read the range, not one number.
- `reports/reversion_by_day_type.py`: splits both reversion strategies' trades (SPY and QQQ 5min, usual costs) into trend days (the third of sessions with the biggest open-to-close move, per symbol) vs. other days and writes `reports/reversion_by_day_type.html` (`uv run -m reports.reversion_by_day_type`, a few minutes). Trend days are picked with hindsight, so this shows where the edge goes, not a tradable filter.
- `judge/scorecard.py` and `judge/standards.yaml`: the lab's standards as a judge. `uv run -m judge.scorecard <strategy> --symbol QQQ --set name=value --trials N` runs eight rules and prints PASS or FAIL for each (at least 200 trades, Sharpe after costs, walk-forward out-of-sample Sharpe with re-tuning, the fixed settings' Sharpe on the same months, Monte Carlo drawdown at the 5th percentile, break-even cost multiple, Deflated Sharpe, parameter noise), exits 1 if any fails; `scorecard(name, symbol, settings, trials=)` is the function for research loops. Thresholds and the reasoning for each live in the YAML; change them there. Everything runs in one process pool, 30 s to 2 minutes per strategy. Walk-forward re-tunes each window, so it judges the strategy plus its tuning; a separate rule holds the fixed settings to the same bar on the same months. `--trials` is how many settings the research says it tried (the Deflated Sharpe needs it; default 100 is a guess and the output says "assumed"). It is only a claim: every run is also written to the trial ledger `research/trials.csv` (time, commit, strategy, symbol, full settings), and the Deflated Sharpe uses the larger of the claim and the number of distinct (symbol, settings) rows the ledger holds for that strategy, so `--trials` can only raise the count (the note under rule 7 says whether it came from "claimed", "assumed" or "ledger"). Rerunning the same settings is not a new trial; a run that crashes still counts. The ledger is written before the backtests start, and the judge refuses to run if the file has fewer rows than the committed copy, so commit it often. Every run, finished or crashed, also appends one line to `research/audit_log.jsonl` (time, commit and whether the code was dirty, command, settings, seeds, hash of the standards used, trial counts, pass/fail per rule). Both files are append-only and locked against the agent like `judge/` itself; reading them is fine. Tests: `tests/test_trial_ledger.py`. A new strategy needs an entry in `STRATEGIES` (its tunable settings and ranges). Tests: `tests/test_scorecard.py` (pure parts only).
- `research/journal.md` and `research/cards/`: the idea journal (ranked by promise and cost to test) and one strategy card per finished experiment (rules, settings, full scorecard, verdict, next step). Failed ideas get a card too. H1 (trend-day filter, `max_open_distance_atr` on both reversion strategies, helpers in `strategies/session_clock.py`) failed the judge.
- `research/LOOP.md` and `.claude/agents/researcher-{breakout-momentum,mean-reversion,time-of-day}.md`: the research factory. `LOOP.md` is the one procedure (pre-register the card, cheap check, spec, code with tests, judge, card with the scorecard pasted verbatim, journal row, commit by path) with the budget (8 judge runs, 1 new strategy per idea) and the lessons so far. Each agent takes ONE journal idea of its family (`research/families.txt` maps ids to families), cannot edit the judge or read the holdout (same hooks), and stops at its budget. A new strategy cannot be judged until the user adds its `STRATEGIES` entry by hand; the agent leaves the exact entry in `research/requests/<id>_strategies_entry.md` and sets the journal Status to `blocked: needs STRATEGIES entry`.
- `scripts/research_batch.sh`: one `claude -p` session per untested journal idea (`--dry-run` shows the plan). `--parallel` runs one lane per family side by side as the matching agent, with one shared `--budget-minutes` (`--max-ideas` then counts per family). All lanes share one checkout, so they commit only their own files; the script itself commits the two judge-written ledger files after each idea (the agents are locked out of `git add` for them) and builds the leaderboard at the end. The Stop hook `require_commit.py` looks at the whole tree, so a lane can be told to commit while another lane's files are still open; the agents are told to ignore that.
- `research/leaderboard.py` (`uv run -m research.leaderboard`, about a minute, writes `research/leaderboard.md`): reads the audit log and the SCORECARD blocks pasted into `research/cards/`, drops exact duplicates (same strategy, symbol and full settings; audit beats card, later beats earlier), ranks by rules passed, then Deflated Sharpe, then Sharpe, and drops any run whose daily returns correlate above 0.7 with a better run already kept (`--threshold`). Daily returns are not in the audit log, so each run is re-backtested once on the research cache (cached in `research/leaderboard_cache/`, gitignored). Card runs made before the holdout split are flagged. Tests: `tests/test_leaderboard.py`.
- `notebooks/`: exploratory Jupyter notebooks.
